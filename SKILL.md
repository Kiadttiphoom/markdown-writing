# Markdown Document Writing

Create Markdown documents that help their intended readers find information, understand decisions, and act on the result. Match the user's language and tone.

## Workflow

1. Identify the purpose, audience, language, and requested output location from the user and available context. Read existing documents and relevant source material before editing.
2. Preserve user requirements, existing facts, and valid technical details. Distinguish current implementation, proposals, assumptions, and decisions still required. Do not invent data, links, commands, test results, or completed features; mark unknowns clearly.
3. Structure the document around the reader's needs. Lead with the purpose or outcome, use informative headings in a logical hierarchy, and keep paragraphs focused. Use lists for parallel items or steps, and tables when they make comparisons clearer.
4. Use readable Markdown with blank lines around headings, lists, tables, and fenced blocks. Label code fences by language where appropriate; use descriptive links. Add diagrams only when they clarify the content and the target renderer supports them.
5. Review the saved file for clarity, consistent terminology, heading hierarchy, balanced code fences, and contradictions. Check relevant links and paths when practical. Preserve existing content outside the requested scope.
6. Report what changed and checks actually performed, including any material limitations or unresolved decisions.

## Presentation

- Write clear, direct sentences appropriate to the audience; use emphasis sparingly.
- Prefer short, useful headings and avoid decorative sections that do not help the reader.
- Avoid overly wide tables or deeply nested lists when paragraphs or smaller tables are easier to read.
- For technical specifications, show what is known, what is proposed, and what must be confirmed. Keep meaningful constraints and examples intact.
